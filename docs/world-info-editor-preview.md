# 世界书编辑器隔离验证

## 启动与停止

需要 Node.js 20 或更新版本。在仓库根目录运行：

```sh
npm run preview:world-info-editor
```

在浏览器打开 <http://127.0.0.1:4173/>。页面加载后自动打开世界书管理工作台；关闭工作台后，可通过页面按钮或悬浮入口重新打开。

- 服务仅监听 `127.0.0.1`，不对局域网开放。
- 不需要构建或额外依赖；直接提供仓库当前的源码与 CSS。
- 修改源码后刷新浏览器即可加载新代码；没有热更新。
- 在启动服务的终端按 `Ctrl+C` 停止。
- 如果端口已被占用，使用 `npm run preview:world-info-editor -- 4174`，以终端打印的地址为准。

## 隔离边界

页面使用生产环境的 `ShellController`、功能注册与懒加载、工作台 iframe、世界书管理页面及运行时，不复制另一套编辑器实现。只替换世界书读写和扩展设置的宿主接口。

- 初始提供 80 条虚构世界书条目，默认最大化工作台、青灰主题。
- 世界书、设置、自动保存和手动保存全部只驻当前页面内存，不连接 TauriTavern，不访问真实世界书或模型服务。
- 刷新整个浏览器页面会重置示例数据、草稿、滚动位置和正文框高度。
- 编辑器内的“刷新”按钮只重新读取当前内存世界书，不会重置示例。
- 正文框的手动高度只保证本次编辑器实例内保持，不跨浏览器刷新或重新挂载保存。
- 这能验证 Chrome 中的布局和交互，不能替代 TauriTavern WebView、宿主文件持久化或手机软键盘的实机验收。

## 手动验收步骤

建议先使用约 1440 × 1000 的桌面浏览器窗口，避免窄容器布局隐藏左侧列表。

### 左侧列表滚动

1. 将左侧列表滚到第 50 条之后。
2. 点击当前可见的几个条目，确认详情和选中高亮更新，而列表没有回到顶部。
3. 修改当前条目的标题，立即点击另一条目，确认草稿保存后列表仍保留位置。
4. 滚到列表末尾，连续点击第 78、79、80 条，确认没有回到最上方。
5. 主动将列表滚回顶部，再切换条目，确认不会被恢复到旧的靠后位置。

### 正文框手动高度

1. 用鼠标拖拽正文框右下角的原生调整手柄，将文本框拉高。
2. 展开或折叠底部的高级触发设置，确认重绘后高度不变。
3. 切换几个条目，确认正文切换，但文本框保持手动高度。
4. 再将文本框拖小，继续切换条目，确认保留最新高度而不是第一次调整的高度。
5. 调整浏览器宽度，确认文本框宽度仍自适应，不被手动高度锁定。

### 全屏写作目录

1. 点击“全屏写作”，确认左侧目录只显示标题和启用状态，右侧显示当前正文。
2. 在目录中搜索标题或关键词，切换“常驻 / 已启用 / 已禁用 / @深度 / 含图片”，确认结果与管理界面一致。
3. 修改正文后立即切换目录条目，确认旧正文已保存、新正文正确显示，且仍处于全屏。
4. 将目录滚到后部再连续切换条目，确认目录滚动位置保持；搜索和筛选不清空正文或选区。
5. 关闭全屏，确认管理界面保留同一搜索和筛选状态。
6. 在窄浏览器窗口中用“目录”按钮展开侧栏，选择条目后确认目录收起，正文仍有完整可用宽度。

## 浏览器自动化提示

使用独立命名会话，不占用用户正在使用的浏览器标签页。工作台位于 `#tt-toolkit-frame` iframe 内，操作列表和文本框前切换到该 frame；读取诊断时可回到主 frame。

浏览器控制台可读取 `window.qa.ready`、`window.qa.writes` 和 `window.qa.worldStore`：它们仅包含本页示例数据，便于确认加载完成和内存写入次数。iframe 文档可从 `document.querySelector('#tt-toolkit-frame').contentDocument` 读取。

自动化工具的元素点击可能先将部分被遮挡的卡片完整滚入视野。若要严格验证点击时的 `scrollTop` 不变，使用可见区域内的原生鼠标坐标点击，或记录点击事件发生时的位置，而不是把工具操作前的滚动位置直接当作点击时的位置。正文高度应通过真实鼠标拖拽验证，不用直接赋值样式代替。


预览服务测试覆盖生产源码直读、禁用缓存、URL 异常、无关文件隔离与拒绝 HTTP 写入；DOM 回归测试覆盖连续重绘时的列表滚动及手动高度保留。实际鼠标交互仍按上面的步骤在浏览器验收。
